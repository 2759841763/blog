# SQL实战的一些看法

在实战中，我们抓包可以抓到很多参数，每个参数都有可能存在SQL注入，那怎么判断呢？

接下来我们来聊聊





## 第一步：找参数

对于sql注入，参数是一个很重要的点，所以要认真排查每一个参数重点标记的参数，

list?keyword= search?name= detail?id= query?account= export?class_id=等，

找老系统的参数，更好注入



## 第二步：判断是否存在SQL注入

### 先尝试判断闭合方式

**最常见的探测手法**

一般情况我们都是进行1，3单引号报错，2，4单引号不报错，这种快速探测的手法，这个也是我一直的一个误区

但是真实情况并不一定，有时很多系统把错误语法和空结果都映射成同一种默认页面（盲注特征）

所以**1'不报错不等于没住人**

```
类型：
2-1是否返回1 
1 AND 1=1是否有变化
数字型生效=数字型；1'才变=字符型；都不变=intval/参数化



闭合：
1'和1"谁发生变化
单/双引号



括号：
试 1) 1') 1' ) --
配平语法



尾部:
后面还有条件用 -- /#；搜索型尾部 %'要补全
注释/补全

看响应差异
报错 > 布尔 > 时间 > UNION
真假条件必须产生响应差异才算注入
```

**判断注入的唯一标准是「AND 1=1 和 AND 1=2有没有响应差异」，不是单引号报不报错。学校很多系统把语法错误和空结果都映射成同一种默认页（盲注特征），1' 不报错 ≠没注入。**



## 第三步：绕waf

系统常挂安全狗/雷池/自研过滤器，核心坑是：

- 过滤器查原始 URL，不查解码后的值 → 绕过就是「全部 URL 编码」：'→%27、(→%28、空格→%20，漏编一个就被拦。

- 断连型 WAF（拦 and/union→ HTTP 000）→ %20AND%20、大小写混用、/**/ 代空格。
- 实战验证：ibw CMS 用 LIKE 代替 = 绕过站点防火墙，通杀多站。



## 第四步：数据库指纹 + 闭合组合试错表

先识别DB：

![image-20261112230448197](/img/实战/image-20261112230448197.png)

盲注下闭合试错表逐个打，看哪个让真假条件开始产生差异：

当然如果waf去拦截了and和=号这种就要绕过

```
1' AND '1'='1        字符型无括号
1' ) AND ('1'='1     字符型+左括号
1" AND "1"="1        双引号
1 AND 1=1            数字型
1) AND (1=1          数字型+括号
1' AND '1'='1' -- -  字符型+注释尾
```

#### 案例四

在做渗透测试中，发现有一个参数存在SQL注入

id=1一个单引号闭合，发现302跳转，两个单引号闭合依旧302跳转

只要输入单引号就跳转，正常情况就不在测试，但是确实存在SQL注入



这里就必须要讲到，有时候单引号报错了，但是后端正常让报错重定向到正常页面

这样就是无论如何都是无法通过单引号是否报错查看是否存在SQL注入



这时我们需要完整的去测试

我们要尝试通过下面的内容：

```
1' AND '1'='2' -- -
1' AND '1'='1' -- -
1' OR 1=1 -- -
```

发现1=1的情况响应200，1=2情况响应302

这时可以通过响应码去进行观察表达式是否正确，这种就是去盲注即可

#### 案例五

对于参数id=108101是正常的数据

但是cid=108101abc进行字符串拼接触发 SQL 错误

这是考虑应该是字符型闭合方式

但是进行常规尝试都是不行的

```
id=108101 and 1=2
id=108101 and 1=1
```



尝试绕waf

```
108101/**/AND/**/1=1
108101/**/AND/**/1=2
```

全局黑名单**大小写敏感**：小写 and 、 config 被拦，大写 AND 、 CONFIG_BASE 可通过。

/**/ 代替空格；末尾 -- 注释应用拼接的尾部 SQL（ --+ 因 + 被过滤而失败）。

单引号/括号本漏洞不需要；双引号 %22 被拦，但**原始** " **可通过**，因此可用 "admin" 引用 DM 保

留字表。

这些都能绕过，尝试构造payload即可
